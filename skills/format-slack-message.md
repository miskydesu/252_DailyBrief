# Skill: Slackメッセージフォーマット

Canvas（長文）とDM（通知）のフォーマット規約。

## Slack Canvas（長文レポート）

### 命名規則

`📅 [YYYY-MM-DD] {user.name} デイリーブリーフ`

例: `📅 2026-05-05 松林 デイリーブリーフ`

### 配置先

`user.output.slack.canvas_channel` で指定されたチャンネル内にCanvasを作成。
チャンネルは個人専用（例: `#daily-brief-matsubayashi`）を推奨。
社内に見せたくない情報が含まれるため、**プライベートチャンネル必須**。

### 本文構造

CLAUDE.md の Routine A 出力フォーマットに従う。Markdown記法はSlack Canvasの仕様に合わせる：

- 見出し: `#`, `##`, `###`
- 強調: `**text**`
- 表: 標準Markdownテーブル
- リンク: `[text](url)`
- チェックボックス: `- [ ] text`

### リンク埋め込みの原則

- ミーティングごとに必ず以下を末尾に付ける：
  - 📎 議事録（Driveファイル直リンク）
  - 🎥 録画（Meet録画 or Driveの動画ファイル）
  - 📅 カレンダー（Google CalendarのイベントURL）
- 録画/メモが存在しない場合は省略（無理にリンクしない）

## Slack DM（22:00通知）

### 文面（daily-report）

```
📊 今日のレポート公開しました
👉 <Canvas URL|本日のデイリーブリーフ>

📋 ミーティング: {N}件 / ✅ アクション: {M}件 / 💬 重要相談: {K}件
```

- Slack の mrkdwn記法（`<URL|表示テキスト>`）を使用
- 1メッセージで完結。スレッド不要。

### 文面（meeting-prep、会議1件あたり）

```
🗓 *2日後のMTG準備*: {会議タイトル} ({日付} {時刻})

📝 *前回 ({前回日付}) の要点*
{要点を3行以内で}

✋ *持ち越し宿題*
- {担当}: {タスク} → {状況確認の問いかけ}
- ...

💡 *次回アジェンダ案 (たたき台)*
1. {項目}
2. {項目}
3. {項目}

📎 <{議事録URL}|前回議事録> / 📅 <{カレンダーURL}|カレンダー>
```

- 会議が複数ある場合は**1会議1メッセージ**で連続送信（スレッドではなく独立メッセージ）
- 朝の通知なので、各メッセージは長すぎない（モバイルで5秒で要点が掴めるサイズ）

## エラー通知のDM

```
⚠️ *Daily Brief 実行エラー*
ルーチン: {daily-report or meeting-prep}
時刻: {実行時刻}
エラー: {エラー概要}

詳細ログ: <{ログURL}|GitHub>
```

review_recipients にも同じメッセージを送る（最初の2週間）。

## 文体・トーン

- **敬語は使わない**（本人へのDMなので）
- **絵文字は構造マーカーとしてのみ**使用（装飾としては使わない）
- **数字や固有名詞は省略しない**
- 推測した内容には必ず「(推定)」「(要確認)」などのマーカーを付ける
